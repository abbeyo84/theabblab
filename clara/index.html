Join the tailnet

You are a new device and you want in. Read this once, top to bottom, and you will not need help. Two minutes if you follow the order. Every command below is copyable.

Step 0

Know what you are joining

  • Tailnet: one private network owned by Nicholas.
  • MagicDNS suffix: tail3681ff.ts.net — every machine is reachable as <hostname>.tail3681ff.ts.net, so you never memorize an IP.
  • Approval is human. Nicholas approves every new device in the admin console. Nobody else can, and no device can approve itself. Do not ask a peer to approve you — it will not work.
  • Hostname: lowercase, short, and not already in the roster above. thinkpad-x is good.
  • One account: the whole tailnet runs on a single owner account. Sign in with that, not a second identity.

Step 1

Install Tailscale

Same client everywhere. Only the install path differs.

Windows · macOS · iOS · Android

Install from tailscale.com/download or your app store. Open it and sign in with the owner account. No terminal step — skip to Step 3.

Linux — Debian, Ubuntu, Mint

curl -fsSL https://tailscale.com/install.sh | sh

Read an install script before piping it to a shell, especially one you did not download yourself. The official Tailscale script is safe; the habit is what matters.

Linux — antiX, Devuan, or any runit box

The Debian package ships only systemd units. On a runit machine nothing starts tailscaled and /var/lib/tailscale is never created — so the machine looks network-broken when the real fault is init. The service must be written by hand:

# 1. Create the state dirs
sudo install -d -m 0700 /var/lib/tailscale
sudo install -d -m 0750 /var/cache/tailscale

# 2. Write the run script (foreground — tailscaled does not fork)
sudo install -d -m 0755 /etc/sv/tailscaled
sudo tee /etc/sv/tailscaled/run >/dev/null <<'EOF'
#!/usr/bin/sh
set -e
[ -x /usr/sbin/tailscaled ] || exit 161
mkdir -p /run/tailscale /var/lib/tailscale /var/cache/tailscale
chmod 0755 /run/tailscale
exec 2>&1
exec /usr/sbin/tailscaled \
  --state=/var/lib/tailscale/tailscaled.state \
  --socket=/run/tailscale/tailscaled.sock \
  --port=41641
EOF
sudo chmod 0755 /etc/sv/tailscaled/run

# 3. Enable at boot and start it now
sudo ln -sfn /etc/sv/tailscaled /etc/service/tailscaled
sudo sv start tailscaled && sudo sv status tailscaled

A runit service stuck at down … normally up, want up forever is the classic fork symptom — the daemon backgrounded itself and runsv restarts it once a second, silently. Keep the daemon in the foreground as above. If a log runner exists, copy antiX's bundled /etc/sv/svlogd/log-run into /etc/sv/tailscaled/log/run rather than writing your own. And exit 161 means "not wanted", not "failed".

Step 2

Join the network

sudo tailscale up --hostname=your-device-name
  • Do not add --accept-routes. There is no subnet router on this tailnet, so it is unnecessary and can create confusing routing. Plain tailscale up is correct here.
  • The command prints a one-time login URL. Open it on this device, or on any device already signed in as the tailnet owner — Nicholas does not have to be standing at the new machine, because the URL encodes this node's identity.
  • The URL expires within minutes. Hand it over immediately; an expired link looks identical to "nothing happened" at both ends. Stale? Re-run tailscale up for a fresh one. Never reuse a URL read earlier.
  • On a runit box the CLI may answer checkprefs access denied even with a readable socket. Fix once with sudo tailscale set --operator=$USER; after that this user manages the node without repeated root.

Step 3

Prove it from your side

tailscale status
tailscale ping abbeyo-ai
  • pong means the path works. direct … in X ms is ideal. via DERP(tor) means a relay carried it — also a success, just slower. iOS devices sit on relay routinely. DERP is not a failure.
  • tailscale status should list abbeyo-ai as a peer. If a machine shows offline, last seen <time>, it is simply asleep — not a fault on your side.
  • If you get no reply at all, run tailscale status again and read your own line: logged out and needs approval are different states with different fixes.

Step 4

Your device appears under Machines in the admin console the moment it logs in, but it cannot reach anyone until it is approved. Once he clicks Approve, the whole tailnet opens to you. Nothing more is needed from your side — and nobody else can complete this step for you.

What the tailnet gives you

The point is not a ping. It is that every machine can be used from every other machine, deliberately, without exposing anything to the open internet.

One shell, every box

SSH by name over MagicDNS. No IP bookkeeping, no port forwarding, no certificate arguments.

One dashboard

The Control UI lives on the gateway and reaches the tailnet only. Paired phones and tablets talk to it over the same wire.

One storage pool

FLEETSTORE on the gateway, shared to Linux and macOS alike, with a folder per machine and an INBOX for handoffs.

Split the work

Think on the Linux gateway, act on the Mac node. Heavy builds, Mac-only tooling, and extra browsers go where the hardware fits.

Nothing public

CGNAT addresses route only inside the tailnet. A device that is not on the tailnet cannot see the fleet at all, and no port is opened to the internet.

Rooms that keep their names

Muse, Hermes, Grok Build, and I stay distinct. Different runtimes, different machines, one fleet, no identity merges.

When it does not work

Nine out of ten tailnet problems are one of these. Read the symptom, apply the fix, re-run Step 3. Do not skip to reinstalling.

tailscale ping returns no reply, but tailscale status shows the peer online

Read both ends. One vantage point gives a hypothesis, not a finding. If the peer also cannot reach you, look for the box being present but not genuinely running, or for client isolation on the access point. If the peer is offline, last seen <t>, it is asleep — nothing to fix.

muse never answers ping

Expected. Muse reaches the tailnet through an HTTPS tunnel on port 3130, so ICMP is not part of its path. Test it over TCP instead. This is by design, not a down node.

checkprefs access denied on a runit box

The socket is readable but this user is not an operator. Run sudo tailscale set --operator=$USER once — it removes the need for root on every later command.

The service shows down … normally up, want up forever

Fork symptom. The daemon backgrounded itself and the supervisor keeps restarting it once a second. Make it run in the foreground. Confirm by checking the pid is stable across a wait, not by reading one status line.

Connected, but names do not resolve

Compare getent hosts abbeyo-ai with a direct dig @1.1.1.1 abbeyo-ai. If only the direct query answers, the resolver list is broken — usually a resolv.conf holding only the Tailscale resolver while the link is perfectly fine. Fix resolution before touching the radio.

A Linux box has two addresses on one wifi interface and keeps dropping

Two DHCP clients are fighting over one interface. Make exactly one own it in config and restart — never hot-kill the network manager, or you may lose every path into the box at once. A duplicate address is the symptom of the duel, not a separate fault.

A USB wifi dongle changed name after a reboot

Interfaces are not stable identities on USB wifi. The dongle can return as wlan1 on one boot and wlan2 on the next, orphaning per-interface config. Never hardcode an interface name in a boot hook or profile — wait on a condition instead, and re-resolve the address each session.

Both boxes are on the same wifi and reach the gateway, but not each other

The access point is isolating clients from one another. One router setting, not a client fault, and not band separation — checking the band alone sends you to the wrong fix.

A laptop that lost its DHCP client leaves both the tailnet and the LAN

There is no recovery path without physical hands. Never sever your own access path on a remote box. Change network management in config, write the fix so it survives reboot, then reboot — never hot-kill it as a "quick test".

Still stuck? Paste the raw output of tailscale status, tailscale netcheck, and the exact command that failed. Raw output beats a description every time.
